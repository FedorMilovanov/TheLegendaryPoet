# THE LEGENDARY POET

Тёмный люксовый редакторский сайт о великих русских поэтах: биографии, тексты,
глубокий литературный и — там, где это оправдано — христианский разбор.
React 19 + TypeScript + Vite + Tailwind v4 + Framer Motion.

## Начать здесь

Перед любой правкой:

1. [`AGENTS.md`](AGENTS.md) — authority, один lane/branch/PR, проверки и жёсткие запреты;
2. [`PROJECT_CHARTER.md`](PROJECT_CHARTER.md) — владелец, назначение и редакционная позиция;
3. [`docs/WORK_MODES.md`](docs/WORK_MODES.md) — режимы `FAST / LANE / SYSTEM` и пропорциональные проверки;
4. [`docs/LANE_LOCK_POLICY.md`](docs/LANE_LOCK_POLICY.md) — защита активной работы от конкурирующих веток;
5. [`docs/OWNER_INVARIANTS.md`](docs/OWNER_INVARIANTS.md) — устойчивые решения владельца;
6. [`AGENT_ANTI_REGRESSION_PROTOCOL.md`](AGENT_ANTI_REGRESSION_PROTOCOL.md) — контентные и кодовые регрессии;
7. [`docs/SOURCE_ACQUISITION_AND_DRIVE_POLICY.md`](docs/SOURCE_ACQUISITION_AND_DRIVE_POLICY.md) — поиск, дедупликация и загрузка PDF в Google Drive.

Читайте только документы затронутой поверхности. Старый отчёт, чат или закрытый PR — evidence, но не автоматическая текущая истина.

## Текущая активная работа

Большой редакционный марафон ведётся в одной канонической ветке:

```text
branch: editorial/longform-marathon-2026-08
PR: #271
scope: статьи, источники, мифы, права, утверждённые обложки, публикационная очередь и связанный QA
```

Не создавайте вторую ветку, successor, `final`, `latest` или отдельный PR для того же марафона. Узкий direct-main процесс эмблемы в `AGENTS.md` является специальным владельческим исключением только для эмблемы и не распространяется на статьи, исследования и другой UI.

## Разработка

```bash
npm install
npm run dev        # локальный сервер разработки
npm run build      # production-сборка в dist/ (multi-file, хешированные ассеты)
npm run preview    # предпросмотр собранной версии
node scripts/gen-sitemap.mjs   # пересобрать public/sitemap.xml из данных
```

Проверки выбираются по реальному риску diff, а не запускаются механически одним максимальным пакетом. Для контентной или article/data правки применимы, среди прочего:

```bash
npm run validate:library
npm run validate:essays
npm run validate:myths
npm run validate:citations
npm run validate:covers
npm run validate:style
npm run typecheck
npm run build
```

Зелёный check на старом head не доказывает новый head. Merge, production-like build и live production — три разные границы.

## Структура

- `src/pages/*` — маршруты: `/`, `/poets`, `/poets/:id`, `/articles`, `/articles/:id`, `/music`, `/about`, 404.
- `src/data/library/*` — данные: по одному модулю на поэта + `articles.ts`, `musicTracks.ts`.
- `src/data/essays/*` — большие статьи универсального типизированного Essay-движка.
- `src/config/site.ts` — **единый источник** ссылок на каналы и контактов.
- `src/components/community/*`, `src/utils/communityStore.ts` — локальный прототип оценок/комментариев.
- `src/hooks/useSeo.ts` — пер-страничные title/description/OG/canonical.
- `src/docs/THEOLOGICAL_GUIDELINES.md` — обязательные правила богословских выводов.
- `docs/research/*` — source maps, myth ledgers, visual/rights matrices и publication gates; это research, а не автоматически публичные routes.
- `docs/IMAGE_PROMPTS.md` — промты и инструкция по подстановке аутентичных изображений.
- `docs/BRAND_EMBLEM.md` — каноническая эмблема, карта иконок и бренд-проверки.

Новая большая статья создаётся в существующем универсальном Essay-движке. Одноразовая страница или частный компонент не создаются, пока типизированные блоки способны выразить материал.

## Источники и Google Drive

Широкий поиск — не автоматическая загрузка. По запросу владельца проводится 40+ discovery-проход, после чего в Drive попадают только источники, которые:

- закрывают конкретный пробел активной статьи;
- имеют ясную библиографическую идентичность и стабильную item page;
- законно доступны;
- отсутствуют во всех существующих библиотеках и batches;
- проверены по названию, изданию, URL, страницам, размеру и SHA-256;
- снабжены provenance, rights status и text-layer status.

Не создавать `FINAL`, `LATEST`, `ULTIMATE`, `COPY`, `(1)` и похожие копии. Исходники, права/manifest, редакционные материалы и publication exports хранятся раздельно.

## Публикация на GitHub Pages

Всё настроено под project‑страницу `https://<owner>.github.io/TheLegendaryPoet/`:

1. В настройках репозитория: **Settings → Pages → Source: GitHub Actions**.
2. Пуш в `main` или ветку деплоя запускает `.github/workflows/deploy.yml`.
3. `vite.config.ts` `base` = `/TheLegendaryPoet/`; deep‑ссылки работают через `404.html`‑фолбэк.
4. Для кастомного домена задаётся `VITE_BASE=/`, обновляются `siteConfig.url`, OG URL и `public/CNAME`.

Успешный merge не является доказательством деплоя. Production заявляется только при same-SHA build и отдельном live witness.

## Редакционные стандарты

1. **Никаких библейских разборов ради обязательной морали.** Комментарий появляется только там, где материал реально ведёт к вопросам Бога, греха, веры, покаяния или надежды.
2. **Не делать поэтов христианами задним числом.** Талант, библейский образ, религиозная тоска и красивый финал не доказывают веру.
3. **Подлинный библейский образ объяснять как источник и художественное преломление**, а не как автоматическое исповедание автора.
4. **Нравственная оценка должна быть прямой, но доказательной.** Можно назвать подтверждённый поступок; нельзя выдумать мотив, диагноз или тайный последний час.
5. **Канонические тексты, цитаты, даты и спорные утверждения сверяются по сильной иерархии источников.** Десять пересказов одного мемуара не являются десятью независимыми свидетельствами.
6. **Реконструкция не является архивом.** `coverKind`, alt, credit, provenance, source URL и checksum обновляются атомарно.
7. **`HOLD` лучше правдоподобной лжи.** Статья не получает публичный route или дату до закрытия source, rights, visual, content и browser gates.

Формула проекта: **точность без обеления, прямота без сенсационности, сострадание без сентиментальной лжи**.

## Бренд

Каноническая эмблема и её точный визуальный workflow защищены в [`AGENTS.md`](AGENTS.md) и [`docs/BRAND_EMBLEM.md`](docs/BRAND_EMBLEM.md). Green CI доказывает техническую целостность, но не визуальное сходство; для эмблемы обязательны exact-reference comparisons и owner review.

## Лицензия

Общественное достояние автора не означает, что любое современное издание, предисловие, фотография или цифровая реставрация свободны от отдельных прав. Права на код и оригинальные редакционные материалы должны быть оформлены до публичного релиза.
