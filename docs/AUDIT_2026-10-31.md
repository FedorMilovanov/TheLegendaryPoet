## 1. Что закрыто этой волной

### 1.1 Одиннадцать ложных предупреждений о цитировании

Каждый прогон печатал одиннадцать предупреждений «у цитируемого источника нет URL».
Все одиннадцать приходились на три источника: лист в названном фонде РГАЛИ,
печатное факсимиле в томе ИМЛИ и расписка, опубликованная в летописи ИМЛИ. Публичного
URL у них нет, и выдумывать его хуже, чем не давать вовсе; место хранения каждый из
них называет в своей note и через институцию.

Правило уже существовало в репозитории — валидатор публикации Есенина II считает
источник неполным, только если у него нет ни URL, ни note, ни institution. Общий
валидатор цитирования теперь задаёт тот же вопрос.

Замерено до правки: **358 источников, 3 без URL, 0 без note и institution.** То есть
ни один из одиннадцати сигналов не был реальным пробелом, и реальный пробел по-прежнему
не останется незамеченным.

Предупреждения гейта: 15 → 4.

### 1.2 Английская рабочая лексика в русских эссе

`provenance`, `upstream`, `staged`, `gate`, `page-witness`, `item`, `acquisition
boundary`, `controlling publication`, `holder readback`, `Direct holder inspection` —
наша внутренняя терминология, которая просочилась в читательский русский текст.
Не только в staged-черновике Бениславской: **тринадцать одинаковых note в
опубликованном эссе Есенина II были целиком на английском.**

Переведено пословно, смысл сохранён:

| было | стало |
| --- | --- |
| архивную provenance | архивную атрибуцию |
| upstream-источниками | исходными источниками |
| staged-версия / staged draft | рабочая версия |
| публикационный gate | публикационный допуск |
| page-witness | постраничное свидетельство |
| 14-item reconciliation | сверка четырнадцати позиций |
| controlling publication | контрольное издание |
| Direct holder inspection | непосредственный просмотр экземпляра у держателя |

Один пин поехал вместе с текстом: `benislavskayaPublished.ts` находит заменяемую
сноску по первым словам, поэтому якорь следует за новой формулировкой. Пин поймал
рассинхрон сразу (`replacedBoundaryCount: 0`) — это сработал гард, а не помеха.

Оставлено дословно и намеренно: формулировка прав Библиотеки Конгресса в кредите

## 4. Как воспроизводить браузерный прогон

Этот раздел существует, потому что я потратил на него два прогона, и он сэкономит их
следующему. **Один хост не может обслужить все спекки**, поэтому CI обслуживает группы
разными серверами, а локальный «запустить всё на одном» неизбежно даёт ложные падения.

| группа | хост | результат |
| --- | --- | --- |
| 29 спеков (основная масса) | `npm run preview` (SPA-fallback: неизвестный путь → 200) | **379 passed, 0 failed**, 20 skipped |
| `site-route-integrity` | `node scripts/serve-pages-static.mjs dist 4173` (Pages-like: чистый URL → документ, неизвестный → 404) | **44 passed** |
| `hall-web-runtime` | свой конфиг `qa/hall-web-runtime/playwright.config.mjs` и своя сборка | **4 passed** |
| `home-media-perf`, `home-polish` | свой конфиг `playwright.home-polish.config.mjs`, проект `home-desktop` | **7 passed** |
| `hover-stability` | `vite preview` | **8 passed, 1 не проходит**: essay-поверхность ждёт удалённую плашку LOC |
| `analytics-route`, `painted-contrast` | только CI: нужны `VITE_GA_ID` / `VITE_YANDEX_METRIKA_ID` | локально падают на «Аналитика: Не настроена» |

Итого локально: **442 passed, 0 необъяснённых падений**, один кейс заблокирован
отсутствием egress и зелёный в CI.

Две ошибки, которые здесь легко повторить:

- Сборка должна быть полной: `VITE_BASE=/ npm run sitemap && npm run build && npm run
  prerender`. Без `prerender` в `dist/` 6 документов вместо 38, и любые проверки
  маршрутов валятся на достоверной причине, но не по делу.
- Сервер надо перезапускать **после** сборки. `vite preview` кэширует дерево файлов
  при старте; запущенный до сборки, он отдаёт SPA-оболочку на уже существующие пути —
  именно так у меня появились семь ложных падений `site-route-integrity`.
