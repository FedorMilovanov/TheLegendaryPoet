## 1. Исправление: `mobile-webkit-isolated.spec.mjs` не осиротевший

Ранее этот файл числился «единственным осиротевшим спеком: ни workflow, ни
раннер его не выполняют». **Это неверно.**

Цепочка выполнения:

```
.github/workflows/manual-browser-qa.yml:220
  └─ node scripts/run-webkit-home-reveal-process-isolated.mjs
       └─ npx playwright test qa/mobile-home-webkit.spec.mjs --project=iphone-safari --grep <название>
            └─ qa/mobile-home-webkit.spec.mjs:3  import './mobile-webkit-isolated.spec.mjs';
```

Спек подключается через side-effect import, поэтому статический поиск имени
файла по `.github/` его и не находил. Проверено, что все grep-паттерны раннера
совпадают с реальными названиями тестов:

- названия секций собираются динамически — `test(\`WebKit home principal section
  ${section.slug} reveals in a fresh context\`)`, где `HOME_SECTIONS` =
  `poet-count`, `poem-of-day`, `featured-poets`, `faith-culture`;
- названия маршрутов — `test(\`WebKit ${name} route keeps one representative lazy
  landmark and runtime stable\`)`, где `ROUTES` = `poets`, `ratings`, `articles`,
  `music`, `archive`, `about`, `hall`, `not-found`.

Пункт закрыт: покрытие есть. `scripts/validate-browser-runtime.ts` (проверки
этого файла и раннера) корректен и не содержит ложного утверждения — править
код не потребовалось.

### Полнота покрытия спеков

Заодно проверены все `qa/*.spec.mjs`: файлов без ссылок из `.github/`,
`playwright*.config.mjs` или `scripts/` — нет. `chromium-core` собирает всё
содержимое `./qa` (`testDir: './qa'`), кроме двух мобильных спеков, у которых

## 3. Доступные имена и размеры целей

Метод: 14 маршрутов (`/`, `/hall`, `/poets`, `/poets/:id`, `/ratings`,
`/articles`, `/essays/:slug`, `/music`, `/music/:id`, `/about`,

2 вьюпорта (1440×1000, 390×844) = 56 загрузок. Собран каждый интерактивный
элемент (`a[href]`, `button`, `input`, `select`, `textarea`, `summary`,
ARIA-роли, `[tabindex]:not([tabindex="-1"])`), для каждого вычислено доступное
имя по каскаду `aria-labelledby` → `aria-label` → `<label>` → `placeholder` →
`title` → собственный текст.

**Итого: 2322 интерактивных элемента.**

| Проверка | Результат |
| --- | ---: |
| Интерактив без доступного имени (WCAG 4.1.2 / 2.4.4) | **0** |
| Интерактив внутри `aria-hidden="true"` | **0** |
| Мелкие цели (<24×24, не inline) | 76, все проходят по исключениям |

### Почему 76 мелких целей не являются нарушением WCAG 2.5.8

Исключение «Spacing» проверялось измерением: окружность диаметром 24 px с
центром в центре цели не должна пересекать ограничивающий прямоугольник другой
цели. Фактические зазоры до ближайшей цели:

| Элемент | Размер, px | Зазор, px | Вердикт |
| --- | --- | ---: | ---: |
| Skip-ссылка `Перейти к содержанию` | 1×1 (скрыта) | 113.7 | в фокусе становится **207×44** — паттерн корректен |
| Чекбокс «Только с голосами» | 13×13 | 35.5 | внутри `<label>`; размер задан агентом (исключение User agent control) |
| `select` порядка релизов | 133×16 / 262×16 | 123.5 | исключение Spacing |
| Ссылки-источники свидетельств | 223–299 × 16.5 | 240.1–295.6 | исключение Spacing |

## 4. Управление фокусом в оверлеях

Проверены три модальных поверхности: `ImmersivePlayer`, `CommandPalette`,
`EssayLightbox`. Чек-лист: вход фокуса, удержание, Escape, возврат фокуса,
изоляция фона.

| | ImmersivePlayer | CommandPalette | EssayLightbox |
| --- | --- | --- | --- |
| `role="dialog"` + `aria-modal="true"` | да | да | да |
| Фокус входит внутрь при открытии | да («Выйти») | да (поле поиска) | да |
| Tab × 18 + Shift+Tab × 8: выходов наружу | **0** | **0** | **0** |
| Escape закрывает | да | да | да |
| Фокус возвращается на триггер | **да** («Погружение») | н/д (открыт с клавиатуры, возврат на `body` — корректно) | **да** |
| Фон изолирован (`inert` + `aria-hidden`) | **да** | **да** | **да** |
| Ошибки страницы | нет | нет | нет |

Все три используют один хук `src/hooks/useDialogSurface.ts` поверх
`src/utils/overlayRuntime.ts` — то есть это не три реализации, а одна общая.
Разница в том, на какой узел ставится `inert`: портальные диалоги (плеер,
лайтбокс) изолируют весь `div#root`, палитра команд — ветку в дереве. Оба
варианта дают эффективную изоляцию `header`, `main` и `footer`.

## 5. Три ошибки измерения, которые сначала выглядели как дефекты

Этот раздел — главная практическая ценность захода. Все три ошибки давали
«красный» результат там, где продукт исправен.

1. **`git stash` вместо checkout нужного коммита.** Проверяя «предсуществующий»
   провал гейта, я откатывал файлы через `git stash push -- <paths>`, но стash
   откатывает к `HEAD`, а `HEAD` уже содержал мой коммит. Получил ложный вывод
   «baseline тоже падает». Правильно — `git checkout <sha> -- <paths>`.
2. **Сборка без `prebuild`.** `npx vite build` не генерирует
   `public/data/essays/` и бренд-артефакты (они в `.gitignore`). Без них все
   страницы эссе отвечают «Статья Не Найдена». Сначала это выглядело как
   катастрофа с контентом; правильная сборка — `npm run build`, который запускает
   `brand:materialize`, `validate:images`, `essay:browser-data`,
   `community:targets`.
3. **Проверка `element.inert` вместо эффективной изоляции.** `inert` ставится на
   ветку-родитель; у потомков собственное свойство `.inert` остаётся `false`,
   хотя они недоступны. По нему два диалога из трёх казались «неизолированными».
   Правильно — `element.closest('[inert],[aria-hidden="true"]')`.

Также: сравнение «вернулся ли фокус» с `document.body` до открытия дало ложное
«не вернулся» — фокус корректно вернулся на кнопку-триггер, а до открытия
активным был `body`, потому что Playwright кликает без предварительного фокуса.
Правильно — помечать триггер маркером и проверять его после закрытия.
