# SEO и подключение поисковых кабинетов

Продакшен-адрес проекта: **https://thelegendarypoet.ru/**

## Что настроено в репозитории

- единый canonical на собственном домене;
- уникальные `title`, `description`, Open Graph и Twitter Cards;
- статические HTML-документы для публичных маршрутов;
- JSON-LD для сайта, организации, статей, исторических лиц, музыки и хлебных крошек;
- `robots.txt` и автоматически генерируемый `sitemap.xml` с достоверным `lastmod` и изображениями;
- Atom-лента `feed.xml` для новых статей и музыкальных публикаций;
- отдельный `404.html` с `noindex,follow` без ложного canonical на главную;
- личный архив и незавершённый Зал Поэтов исключены из sitemap и закрыты через `noindex`;
- автоматическая отправка канонических URL через IndexNow после успешного deploy;
- подтверждение Яндекс.Вебмастера файлом и meta-тегом;
- Google verification через DNS TXT и резервный meta-тег;
- редакционная политика, политика конфиденциальности и аналитика только после согласия;
- CI-контракт, проверяющий sitemap, feed, canonical, structured data, отсутствие `.html`-дублей и корректный 404.

## 1. Яндекс.Вебмастер

Файл подтверждения:

`https://thelegendarypoet.ru/yandex_db80f976814c7327.html`

После подтверждения:

1. Откройте **Индексирование → Файлы Sitemap**.
2. Добавьте `https://thelegendarypoet.ru/sitemap.xml`.
3. Через переобход отправьте главную, `/poets`, `/articles`, `/music` и несколько важнейших материалов.

Файл и meta-тег нельзя удалять: Яндекс периодически перепроверяет права.

## 2. Google Search Console

Предпочтительный ресурс: **Доменный ресурс** `thelegendarypoet.ru`.

DNS-запись создаётся отдельной TXT-записью у DNS-провайдера:

```text
Тип: TXT
Хост: пустой (корень домена)
Значение: google-site-verification=...
```

После подтверждения:

1. Откройте **Файлы Sitemap**.
2. Добавьте `https://thelegendarypoet.ru/sitemap.xml`.
3. Через **Проверку URL** запросите индексирование главной и нескольких ключевых страниц.

Резервный HTML-тег хранится в `search-verification.json` и автоматически внедряется в production HTML при сборке.

## 3. Bing Webmaster Tools

Самый простой путь — **Import from Google Search Console**. После импорта проверить:

- сайт подтверждён;
- sitemap обнаружен;
- IndexNow Insights принимает отправки.

При ручной проверке значение `msvalidate.01` добавляется в поле `bing` файла `search-verification.json`.

## 4. IndexNow

Ключ опубликован по адресу:

`https://thelegendarypoet.ru/189937c25bd79e9d675311b76f9481854c85722f.txt`

Workflow `.github/workflows/indexnow.yml` запускается только после успешного Pages deploy и отправляет URL из sitemap.

## 5. Sitemap, изображения и Atom

Генерация выполняется общей командой:

```bash
npm run seo:generate
```

Результаты:

- `public/sitemap.xml` — канонические индексируемые страницы, `lastmod`, основные изображения;
- `public/feed.xml` — свежие опубликованные статьи и музыкальные релизы.

`lastmod` берётся только из проверенных дат контента. Текущая дата сборки автоматически не подставляется.

## 6. Аналитика и согласие

Код поддерживает:

| GitHub Actions Variable | Значение |
|---|---|
| `VITE_YANDEX_METRIKA_ID` | номер счётчика Яндекс.Метрики |
| `VITE_GA_ID` | идентификатор GA4 вида `G-...` |

Путь: **Settings → Secrets and variables → Actions → Variables**.

Если переменные не заданы, аналитика и баннер согласия полностью отключены. Если заданы, скрипты Google и Яндекса загружаются только после нажатия посетителем «Разрешить». Для SPA-навигации отправляются отдельные просмотры страниц.

## 7. Bing и Pinterest verification

`search-verification.json` хранит только значения `content`, без названий meta-тегов:

```json
{
  "google": "КОД_GOOGLE",
  "bing": "КОД_BING",
  "pinterest": "КОД_PINTEREST"
}
```

Pinterest подключается только при фактическом использовании бизнес-аккаунта Pinterest.

## 8. Что остаётся внешним действием

Репозиторий не может самостоятельно:

- подтвердить домен в интерфейсе Google, Яндекса или Bing;
- создать DNS TXT-запись;
- создать счётчики GA4 и Метрики;
- обеспечить настоящий HTTP 301 на GitHub Pages.

Для старых URL, если они получат внешние ссылки, постоянные 301 следует настроить на CDN/reverse proxy (например, Cloudflare Redirect Rules), а не имитировать клиентским JavaScript.

## Контроль после крупного обновления

1. Убедиться, что CI и Pages deploy зелёные.
2. Открыть `/robots.txt`, `/sitemap.xml`, `/feed.xml` на production-домене.
3. Проверить canonical и robots в исходном HTML ключевой страницы.
4. Проверить structured data через валидаторы Google/Schema.org.
5. Посмотреть отчёты индексирования и Core Web Vitals в Google и Яндексе.
6. Не удалять файлы и meta-теги подтверждения после успешной проверки.
