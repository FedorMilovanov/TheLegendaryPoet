# Approved cover implementation audit — 2026-08-04

## Scope

This release replaces the hero and card artwork for five published essays with the exact user-approved editorial reconstructions. It does not alter article bodies, source cards, citations, routes, or internal documentary images.

Every cover is labelled as a project-created reconstruction. None is represented as an archival photograph, restoration, or primary historical evidence. The article metadata intentionally omits `coverSourceUrl` for these local project works.

## Deterministic production contract

All five production files were rebuilt directly from their approved PNG masters with Pillow `ImageOps.fit`, a 1280 × 720 target, the LANCZOS resampler, WebP method 6, and the quality value recorded below. The generated bytes were accepted only after both file size and SHA-256 matched the pinned release contract.

## Runtime metadata

For each of the five essays:

- `cover` and `cardCover` point to the same dedicated local WebP;
- `coverKind` is `reconstruction`;
- `coverCredit` identifies THE LEGENDARY POET and the historical-reference basis;
- `coverAlt` describes the editorial scene without presenting it as a photograph;
- `coverSourceUrl` is absent because the cover is project-created artwork;
- `dateModified` is 2026-08-04.

## Regression gates

`scripts/validate-essay-covers.ts` pins the five paths, byte sizes, SHA-256 values, alt texts, credits, reconstruction labels, provenance records, and non-duplication of card covers. `scripts/validate-yesenin-part-one-safe-publication.ts` independently pins the approved Yesenin Part I checksum while preserving the article’s source and publication boundaries.

The root `public/images/PROVENANCE.yml` records the master IDs, deterministic recipes, sizes, checksums, origin class, and evidence status for all five assets. `public/sitemap.xml` is regenerated from the same canonical essay metadata so its dates, image URLs, and captions remain stable in a clean checkout.

## Excluded transport history

The abandoned Base64 chunk transport and its temporary workflows are not part of this release. The production change consists only of durable site assets, metadata, provenance, validation, the canonical generated sitemap, and this audit record.
