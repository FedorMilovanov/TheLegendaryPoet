# Общие оценки и комментарии

Публичный сайт остаётся статическим на GitHub Pages. Общие оценки и комментарии обслуживаются отдельным бесплатным Cloudflare-контуром:

`браузер → Cloudflare Worker → D1`

Turnstile используется только для выпуска долговременной анонимной серверной сессии участника. После этого очередь браузера может безопасно повторять записи после временного офлайна, не сохраняя одноразовые Turnstile-токены.

## Почему не доверяем UUID браузера

Локальный `tlp-community-device-v1` остаётся только частью устойчивости текущего браузера и outbox. Он не является доказательством личности и никогда не передаётся Worker как серверная authority.

Worker сам:

- проверяет Turnstile через Siteverify;
- создаёт случайный actor ID и подписывает сессию HMAC-секретом;
- получает адрес соединения из `CF-Connecting-IP`, HMAC-хэширует его отдельным секретом и хранит только 64-символьный hash;
- проверяет, что target действительно существует в release-generated `community-targets.json`;
- применяет сетевые rate budgets;
- пишет в D1 через prepared statements.

Ни actor ID, ни network hash не доступны в публичных read endpoints.

## Бесплатный Cloudflare-контур

Нужны три ресурса в одном Cloudflare-аккаунте:

1. D1 database `the-legendary-poet-community`.
2. Worker `the-legendary-poet-community`.
3. Turnstile Managed widget для `thelegendarypoet.ru` и `www.thelegendarypoet.ru`.

Карта для создания этих Free-ресурсов не является частью нашей архитектурной процедуры. Не переходите на Paid/Upgrade ради этого контура.

## Настройка без секретов в GitHub

Полная инструкция и security invariants находятся в [`workers/community-api/README.md`](../workers/community-api/README.md).

В GitHub Actions нужны только публичные variables:

- `COMMUNITY_API_URL` — HTTPS URL развернутого Worker;
- `TURNSTILE_SITE_KEY` — публичный sitekey Turnstile.

Для production shared mode нужны **обе** переменные. Если URL отсутствует/невалиден или отсутствует sitekey, клиент намеренно остаётся в локальном режиме: это безопаснее, чем создавать удалённую очередь, которая в принципе не сможет выпустить подписанную actor-сессию.

Секреты `COMMUNITY_SESSION_SECRET`, `COMMUNITY_NETWORK_SECRET` и `TURNSTILE_SECRET` должны находиться только в Cloudflare Worker secret store. Они не должны попадать в `VITE_*`, git, GitHub Variables, JS bundle, логи или комментарии PR.

## Локальный режим и отказоустойчивость

Пока полный публичный комплект `COMMUNITY_API_URL` + `TURNSTILE_SITE_KEY` не настроен, community работает в честном локальном режиме: действия принадлежат текущему браузеру.

После полного подключения shared mode локальный v3 outbox остаётся атомарным. Если сеть, Worker или D1 временно недоступны, операция не объявляется синхронизированной: она остаётся в очереди в исходном порядке и повторяется с ограниченным backoff. `429` остаётся retryable и учитывает `Retry-After`; временные `5xx`/сетевые ошибки тоже остаются в очереди. Неповторяемый `4xx` считается терминальным отказом и удаляется как poison-operation, а оптимистическая локальная копия согласуется с серверной правдой.

После ACK оптимистическая локальная копия комментария/оценки больше не остаётся вечным дублем D1: target перечитывается с сервера. Поэтому последующая модерация на сервере не маскируется старой записью из localStorage.

Повтор из фонового/стартового режима не имеет права самовольно показывать Turnstile. Если подписанная actor-сессия истекла или отсутствует, очередь остаётся сохранённой до следующего явного действия читателя. Старые вкладки не могут воскресить уже ACK/reject-операцию: v3 хранит ограниченные settlement tombstones и сливает независимые операции вкладок по ID вместо last-writer-wins замены всего состояния.

Переполнение outbox тоже не скрывается: новая операция не принимается, если для неё нельзя гарантировать устойчивое место. Старые ожидающие записи ради новой не отбрасываются.

## Единый контракт комментария

Клиент, local store и Worker используют один source-of-truth для комментариев:

- текст: 8–2000 Unicode-символов после нормализации переносов/пробелов;
- имя/псевдоним: до 60 Unicode-символов;
- типы: литературный, исторический, этический, исполнительский;
- cooldown комментариев: 20 секунд на actor по всей community-системе, а не отдельно для каждой статьи или стихотворения.

Переносы строк отображаются как переносы. Ввод остаётся plain text: строки вида `<script>` показываются буквально и не исполняются. Превью длинного комментария режется по grapheme boundary при доступном `Intl.Segmenter`, с Unicode-safe fallback без разрыва surrogate pair.

## Чтение, сортировка и состояние

Неуспешный или ещё не завершённый read не изображается как настоящий ноль. UI отдельно показывает loading, error, ready-empty и ready-with-data. Если refresh падает после успешной загрузки, предыдущая сводка и уже полученные комментарии остаются видимыми с честным сообщением об ошибке.

Worker выдаёт комментарии канонически newest-first с cursor pagination. Клиентские «Полезные/Новые» и фильтр по типу применяются только к уже загруженным строкам; пока есть следующая серверная страница, интерфейс прямо обозначает этот scope и сохраняет кнопку загрузки общей ленты даже под фильтром.

Редактор, сортировка и фильтр привязаны к `targetType:targetId`. При переходе A→B несохранённый draft и выбранная оценка A не могут отправиться callback-ом уже в B.

## Доступность

Статусы пользовательских действий имеют live-region semantics: успех — `role=status`/polite, предупреждение — `role=alert`/assertive, сообщения atomic. Сортировка и фильтры используют `aria-pressed`, раскрытие текста — `aria-expanded`, а loading/error комментариев не передаются одним цветом.

## Модерация

Скрытие комментария — административная операция в D1:

```sql
UPDATE tlp_comments SET status = 'hidden' WHERE id = 'comment-id';
```

Возврат:

```sql
UPDATE tlp_comments SET status = 'published' WHERE id = 'comment-id';
```

Публичный endpoint выдаёт только `status = 'published'`. После успешного ACK браузер не держит собственную серверную копию комментария, поэтому скрытый в D1 комментарий исчезает после следующего target refresh, как и должен.
