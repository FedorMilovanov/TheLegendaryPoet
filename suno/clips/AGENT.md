# Протокол агента: SUNO-клипы

## Назначение

Используй этот протокол для запросов на кадры, сцены, раскадровку, исправление
изображений и оживление клипа по песне SUNO. Для Lyrics и музыкального Style сначала
действуют правила `suno/AGENT.md`; этот документ не заменяет их.

## 1. Начало без лишних вопросов

Перед генерацией:

1. прочитай манифест проекта или профильный case;
2. установи последнюю корректировку пользователя — она важнее старого промта;
3. найди утверждённые референсы и уже выбранные кадры;
4. зафиксируй формат, стиль, continuity и что именно нельзя менять;
5. начни с короткого плана текущего раунда и сразу работай.

Не спрашивай то, что уже записано в репозитории. Не требуй полный бриф, если можно
начать с разумного варианта. Вопрос допустим только при реальной развилке, которую
нельзя разрешить из контекста, либо перед внешней публикацией/правовым решением.

## 2. Обязательный режим: раунд из 3 баттлов

Один **баттл** — один вызов генерации с `offer_options: true`, показывающий пользователю
два независимых кандидата. Один стандартный **раунд** — **ровно 3 баттла**, то есть
до шести кандидатов на сравнение.

- Для серии из трёх кадров: один баттл на каждый кадр.
- Для одного трудного кадра: три баттла с одной целью, но с осмысленно изменённой
  стратегией, если причина неудачи известна.
- Повторный раунд тоже состоит из трёх баттлов. Не возвращайся к одиночным попыткам.
- Одиночный/небоевой режим допустим только при прямой просьбе пользователя.
- Независимые баттлы запускай параллельно; каждый должен дать одно standalone-изображение.
- Не проси в одном изображении сетку, контрольный лист, коллаж или несколько вариантов.

Одинаковый промт может дать разный результат. Если ошибка системная, меняй одну
главную переменную: референс, тип редактирования, выражение, масштаб или композицию.
Не переписывай всё без причины.

## 3. Статусы результата

- **Accepted:** пользователь выбрал кандидата, файл сохранён. Только такой кадр может
  стать референсом канона, основой оживления или частью готовой серии.
- **Rejected / `skipped`:** пользователь не выбрал никого, файл не сохранён. Не называй
  результат готовым и не включай его в серию.
- **Aborted:** выполнение прервано; это не завершённый баттл и не accepted.
- **Saved without a clear selection:** файл существует, но каноном становится только
  после явного подтверждения пользователя.
- **Stop:** любое «хватит», «больше не надо», «остановись» отменяет автоматические
  повторы. Следующая работа начинается только с новой инструкции.

После отклонённого концепта сделай короткую диагностику и новый раунд из трёх баттлов.
Если пользователь просит двигаться дальше, не возвращайся к старым отклонённым попыткам.
Не создавай бесконечный цикл молчаливых ремонтов.

## 4. Референсы и независимость кадра

Перед вызовом обозначь в промте роль каждого изображения: композиционная основа,
мастер личности, мастер существа/реквизита или принятый continuity-кадр. Обычно хватает
1–3 референсов. Не добавляй изображение только «чтобы было».

Для редактирования первым передавай тот кадр, который нужно сохранить. Для новой сцены
не называй её «pixel-perfect», если она создаётся заново. Подробнее — [VISUALS.md](./VISUALS.md).

## 5. Порядок производства

1. Сначала зафиксируй план кадров и визуальный канон.
2. Генерируй статику раундами по 3 баттла.
3. Веди короткий статус по кадрам: `pending / battling / accepted / needs-redo / stopped`.
4. После раунда сообщай только фактические выбранные пути и незавершённые кадры.
5. Оживление начинай лишь для accepted-кадров и по [ANIMATION.md](./ANIMATION.md).
6. Для выдачи на скачивание используй `present_file`; не заставляй пользователя искать
   файл в глубокой рабочей вложенности.

## 6. Definition of done

Кадр завершён, когда:

- пользователь выбрал его;
- файл реально существует в workspace;
- формат и отсутствие полос проверены для финального использования;
- личность, реквизит, существо и continuity соответствуют манифесту;
- нет незаявленных людей, текста, водяных знаков и дефектов анатомии;
- выбранный путь записан в проект.

Серия не считается завершённой по количеству вызовов: нужны принятые файлы по всем
запрошенным кадрам либо явное решение пользователя остановиться/пропустить.

Генерация, добавление в Git, публикация и музыкальный релиз — разные действия. Не
выдавай одно за другое и не заявляй о прослушивании/просмотре без фактической проверки.
