# Хранение песен, стилей, изображений и видео

## Можно ли загружать MP3 в репозиторий?

**Да.** Git и этот репозиторий поддерживают MP3; в `public/audio/` уже находятся
треки Блока, Пушкина и Есенина. Но рабочие дубли и опубликованный мастер — разные вещи.

- **Черновые варианты SUNO:** обычно не коммитить. Хранить вне Git или в отдельно
  согласованном большом хранилище, а в проекте записать происхождение и выбранную версию.
- **Финальный MP3 для публикации:** можно размещать в `public/audio/`, но только по
  [music release workflow](../../docs/MUSIC_RELEASE_WORKFLOW.md).
- **Много больших аудио/видео:** не раздувать обычный Git. Заранее выбрать внешнее
  хранилище или осознанно настроить Git LFS; не включать LFS задним числом молча.

## Политика по типам файлов

| Материал | Основное место | В Git? |
|---|---|---|
| Lyrics, Style, Exclude, права и редакторские решения | `suno/` и манифест клипа | Да |
| Манифест клипа, раскадровка, промты, статусы | `suno/clips/projects/` | Да |
| Общие правила и проверенные кейсы | `suno/clips/` | Да |
| Рабочие кандидаты и retry в Arena | `image-search/<project>/` | Не автоматически |
| Утверждённые визуальные мастера | `suno/clips/references/<pack>/` | Да, небольшие кураторские наборы |
| Невыбранные кандидаты, временные crop/canvas | Рабочая область | Нет |
| Черновые MP3 | Внешняя/рабочая область | Обычно нет |
| Финальный MP3 | `public/audio/` | Да, после release-проверок |
| Черновые и мастер-видео | Внешнее хранилище или согласованный LFS | Не в обычный Git по умолчанию |
| Production WebP/JPEG для сайта | `public/images/…` | После оптимизации и интеграции |

## Push в публичную ветку — уже размещение файлов

Merge не является первым моментом доступности: push ветки публичного GitHub-репозитория
уже публикует байты файлов для тех, у кого есть доступ к репозиторию. До такого push проверь
права, приватность и разрешение владельца на размещение референсов и медиа. Это отдельный
барьер до production release и не утверждение о нарушении прав на существующие файлы.

## Публикация музыкального мастера

Для `published` нужны не только байты MP3. Действующий workflow требует, среди прочего:
точную длительность, SHA-256, реальную waveform, обложки, credits/rights, manifest и
дату публикации. Не регистрируй черновик как готовый релиз и не угадывай эти данные.

До публикации отдельно проверяются права на текст (если он не в public domain), музыку,
исполнение/голос и визуальные материалы. Внутренняя подготовка не равна разрешению на выпуск.

## Рабочая область Arena

Вложения из `/tmp` сначала копируй в проектную область внутри repository workspace,
иначе они могут не сохраниться между сессиями. Не храни единственную копию мастера во
временном каталоге. Сгенерированные файлы сохраняются автоматически как рабочие изменения,
но это не означает commit или публикацию.

## Именование

- Кадры: `NN-short-russian-slug.jpg`.
- Повтор: `NN-short-russian-slug-retry-02.jpg` (без `final-final-new`).
- Выбранный кадр: фиксируй точный путь в манифесте; не создавай второй «канон» копированием
  без необходимости.
- Аудио: существующая release-схема проекта, например `poet-work.tlp-YYYY.mp3`.
- Не перезаписывай молча выбранный мастер; новая версия получает новое имя и проверку.

Перед любым массовым перемещением существующих изображений сначала обнови ссылки в
манифесте и убедись, что рабочие референсы не потеряны.
